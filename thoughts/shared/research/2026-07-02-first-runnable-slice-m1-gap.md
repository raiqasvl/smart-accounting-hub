## Research Question

What do we actually need to do to get the app up and running and see the first
results/features — i.e. the first working end-to-end slice? This documents (a) the
verified current state of the codebase, (b) the exact "first result" target, (c) the
ordered work to reach it, and (d) the local-dev runbook to run and observe it.

## Summary

**The repo is a fully-specified, fully-bootstrapped, zero-implementation scaffold.** Every
one of the **61 `.py` files** and **7 `.ts/.tsx` source files** across `packages/`, `apps/`,
and `migrations/` contains **zero executable lines** — only `#`/`//` comment blocks that
precisely specify what to build. The only non-comment lines anywhere are the two placeholder
type aliases in [packages/api-types/src/api.d.ts](packages/api-types/src/api.d.ts), and those
are the empty `Record<string, never>` stub, not generated types.

What genuinely advanced since the [2026-06-10 state doc](thoughts/shared/research/2026-06-10-current-implementation-state.md):
the scaffold was **committed** (5 commits, `71e6191`→`97f66fe`) and **bootstrap was run** —
`.venv` is provisioned with all three workspace packages installed editable and every
third-party dep importing (`fastapi, aiogram, sqlalchemy, alembic, dishka, pydantic`), and
`node_modules` is installed at root + `apps/miniapp` + `packages/api-types`. **No source code
was written.** M1 has not been started in code.

**The "first result" is Milestone M1 "Foundations"** — one vertical auth path:

> `/start` → upsert user + auto-create default book (silent, one transaction) → issue JWT →
> Mini-App reads Telegram `initData`, `POST /auth/telegram` → `GET /me` → renders
> `Hello {name}, book "{name}"`.

Reaching it means filling in the scaffold in dependency order: **config/engine/UoW → 11 ORM
models → single `0001_initial` migration → auth primitives (initData HMAC + JWT) → repos
(users/tg_chats/books) → `auth_service` (the one transaction) → API deps + 3 routers → bot
`/start` handler → Mini-App page**. Infra is only **2 containers** (Postgres 16 + Redis 7);
the three apps run on the host for hot-reload, and a **cloudflared tunnel** exposes the
Mini-App to Telegram.

**Nothing runs today.** `make dev-api`, `make dev-bot`, and `make migrate` all reference
symbols that do not yet exist (`main:app`, a runnable `env.py`, the `0001` migration) — these
are forward references in the scaffold, not defects. Several M1 plan/DoD lines are also stale
relative to the local-dev pivot (5 containers→2, Caddy deferred, eslint→oxlint, Sentry/CI
deferred). Details below.

### 2. The first end-to-end slice (M1) — precise definition

Plan of record: [thoughts/shared/plans/2026-05-01-mvp-scope-and-milestones.md](thoughts/shared/plans/2026-05-01-mvp-scope-and-milestones.md)
(M1 = lines 134–475). The single vertical path M1 must make work:

1. User sends **`/start`** to the bot.
2. Bot `/start` handler ([apps/bot/.../handlers/commands.py](apps/bot/src/smart_accounting_bot/handlers/commands.py))
   calls `smart_accounting.services.*` **directly** (D22 — no HTTP): upserts `users` + `tg_chats`;
   if new, **silently auto-creates** (D21, one transaction) a default personal `book` +
   `book_members(role=OWNER)` + sets `tg_chats.active_book_id`. Base currency from a
   `language_code` heuristic (`ru→RUB, uk→UAH, tr→TRY, de/fr/es/it/pl/nl→EUR, else→USD`).
3. Bot replies with a `WebAppInfo` button pointing at the Mini-App URL.
4. User taps it → Telegram opens the Mini-App (served over the cloudflared HTTPS tunnel).
5. Mini-App ([app/page.tsx](apps/miniapp/src/app/page.tsx)) reads `Telegram.WebApp.initData`
   and `POST /auth/telegram` `{init_data}`.
6. API [routers/auth.py](apps/api/src/smart_accounting_api/routers/auth.py) → `auth_service` →
   `verify_init_data(init_data, BOT_TOKEN)` (HMAC-SHA256, reject `auth_date` >24h) → upsert user
   / auto-create book if new → **issue HS256 JWT** `{sub, book_id, role, exp, iat, jti}`, 30-min
   lifetime (D12). Returns `{access_token, expires_in:1800, user, book}`.
7. Mini-App stores JWT (memory + sessionStorage), `GET /me` with `Authorization: Bearer …`.
8. API [routers/me.py](apps/api/src/smart_accounting_api/routers/me.py) → `deps.current_jwt_claims()`
   verifies JWT → returns `{user, active_book, role, books}`.
9. Mini-App renders `Hello {first_name}, book "{book.name}"`.

**Negative paths (part of DoD):** tampered JWT → **401** on `/me`; tampered initData → **403**
on `/auth/telegram`.

### 4. Ordered work to reach the first result

Ordering follows the locked layering `models ← repositories ← services ← presentation ← UI`
(plan line 128) and the schema-first rule (line 126: single migration before any service code).
The `__init__.py` stubs confirm the M1 file set: repos = `users.py, tg_chats.py, books.py`;
services = `auth_service.py`.

1. **Cherry-pick foundations** (plan §1.2) from `research/AiogramBotTemplate/`: `models/base.py`,
   `models/fields.py`, `common/uow.py`, `database/engine.py`, `ioc.py`, `config.py`, bot
   `storage.py`/`main.py`/`__main__.py`, `migrations/env.py`, `script.py.mako`, `alembic.ini`
   (rename `bot_template`→`smart_accounting`, add MIT attribution). *Everything imports these.*
2. **Config + engine + UoW + Dishka** — make `get_config()` (pydantic-settings, reads `.env`),
   `create_async_engine`/`async_sessionmaker`, the `UoW` async CM, and the `DepsProvider` real.
   *Services need a session factory; `env.py` needs the DSN + `Base.metadata`.*
3. **11 ORM models** — M1-critical first (`user, tg_chat, book, book_member`), then the rest so
   the single migration is complete; un-comment the 11 imports in `models/__init__.py`.
4. **Single Alembic migration `0001_initial`** — all 11 tables in FK order, the two enum types
   (`transaction_kind`, `transaction_direction`), `CREATE EXTENSION ltree, pgcrypto`. Verify with
   `alembic upgrade head && alembic check`. *After this the API and bot can proceed in parallel.*
5. **Auth primitives** — [auth/initdata.py](packages/core/src/smart_accounting/auth/initdata.py)
   (`verify_init_data`, HMAC-SHA256) and [auth/jwt.py](packages/core/src/smart_accounting/auth/jwt.py)
   (`issue_token`/`decode_token`, HS256). *Pure functions, no DB; hypothesis-tested.*
6. **Repositories** — `users.py`, `tg_chats.py`, `books.py` (queries only, no tx, no rules).
7. **`services/auth_service.py`** — the one transaction: `verify_init_data → upsert user →
   auto-create book + book_members(OWNER) + tg_chats (D21) → issue JWT`. *Shared by the API
   router and the bot handler (D22 — two surfaces, one service).*
8. **API deps + routers + wiring** — `deps.py` (`current_jwt_claims`/`current_user`/`current_book_member`),
   `routers/health.py`, `routers/auth.py`, `routers/me.py`, then `main.py` (FastAPI + lifespan +
   Dishka + CORS + **`/api/v1` prefix** — see Open Questions).
9. **Bot `/start` handler** — calls `auth_service` directly; sends the `WebAppInfo` button; boot
   wired in `__main__.py`/`main.py`. *Must not import `models`/`repositories` (D22 grep-guard).*
10. **Mini-App page** — `lib/telegram.ts` (SDK initData), `lib/api-client.ts` (fetch + JWT storage
    + 401), `app/page.tsx` (POST `/auth/telegram` → GET `/me` → render card). Then `pnpm types:gen`
    against the live `/openapi.json` to fill `api-types`.

### 5. Local-dev runbook — how to run and see it

**Infra (only 2 containers, [ops/compose.yml](ops/compose.yml)):** `db` (`postgres:16`, `:5432`,
password via Docker secret `db-password` ← `db/password.txt`, `pg_isready` healthcheck) and
`redis` (`redis:7-alpine`, `:6379`, FSM only). `apps/api`, `apps/bot`, `apps/miniapp`, and
cloudflared run **on the host**.

**Required env — `.env` (from [.env.example](.env.example)):** `DOMAIN` (tunnel host, no scheme),
`ENVIRONMENT`, `DEBUG`, `BOT_TOKEN` + `BOT_USERNAME` (@BotFather), `JWT_SECRET` (32+ bytes) +
`JWT_LIFETIME_SECONDS=1800` (D12), `POSTGRES_DSN` (`postgresql+asyncpg://smart_accounting:<pw>@localhost:5432/smart_accounting`
— `<pw>` must equal `db/password.txt`), `REDIS_DSN`, `LOG_LEVEL`, `FRANKFURTER_BASE_URL` +
`FX_REFRESH_INTERVAL_SECONDS` (M3), `NEXT_PUBLIC_API_BASE_URL` (`https://<tunnel>/api/v1` —
resolve `${DOMAIN}` by hand; Next.js does not shell-interpolate), `NEXT_PUBLIC_BOT_USERNAME`.
Plus **not in `.env`**: `db/password.txt` (Docker secret, D20) — `chmod 600`, kept in sync with
`POSTGRES_DSN`.

```bash
# one-time
make bootstrap
cp .env.example .env    # fill BOT_TOKEN, BOT_USERNAME, JWT_SECRET, DOMAIN; chmod 600 .env
mkdir -p db && python3 -c "import secrets;print(secrets.token_urlsafe(24))" > db/password.txt && chmod 600 db/password.txt
# daily — one process per terminal
make up          # postgres + redis
make migrate     # alembic upgrade head  (needs 0001 + real env.py)
make dev-api     # uvicorn smart_accounting_api.main:app --reload :8000
make dev-bot     # python -m smart_accounting_bot  (long-poll)
make dev-miniapp # next dev :3000
make tunnel      # cloudflared tunnel --url http://localhost:3000
```

After `make tunnel`: paste the printed `https://*.trycloudflare.com` into BotFather (`/myapps` →
Edit Web App URL) **and** into `DOMAIN` + `NEXT_PUBLIC_API_BASE_URL`, then restart api + miniapp —
the trycloudflare URL changes every restart. BotFather setup (bot token, `/setcommands` all 6 —
`/start` lights up in M1 — `/newapp`) is in [docs/bot-setup.md](docs/bot-setup.md).

## Open Questions

1. **`/api/v1` path-prefix.** DoD/narrative use `/api/v1/me`, `/api/v1/auth/telegram`, but the router
   specs declare bare `/me`, `/auth/telegram`, `/healthz`. The prefix lives in
   `NEXT_PUBLIC_API_BASE_URL` and the (deferred) Caddy `@api` rule. Since Caddy isn't in the local
   stack, the implementer must add the `/api/v1` prefix at FastAPI `include_router` or the frontend
   base URL won't match. Unresolved in the plan.
2. **D22 vs `/avg` spec.** [handlers/commands.py](apps/bot/src/smart_accounting_bot/handlers/commands.py)
   comments have the bot's `/avg` (M3) call `repositories.reports.weighted_avg_rate()` **directly** —
   which would violate the hard rule "bot never imports `repositories`". Not an M1 blocker, but the
   spec needs a `services.reports` wrapper before M3.
3. **Doc-vs-reality staleness (fix per "code is right").** No `Dockerfile` and no `ops/Caddyfile`
   exist, yet [docs/bot-setup.md](docs/bot-setup.md) claims "Caddy (already in `ops/compose.yml`)" —
   false (compose is db+redis only). Plan §1.7 still shows a 5-service compose. The Makefile/compose
   already reflect the host-run local-dev pivot; the plan §1.7, the DoD container/Caddy/Sentry/CI
   lines, and that bot-setup sentence should be marked superseded.
4. **Untested round-trip.** No migration has ever been applied and no app has booted; whether the
   documented column types/enums/indexes autogenerate and `alembic check` clean is unverified until
   step 4 of §4 runs.
